# ADR 0013: DDR3 frame store (MIG 7-series behind mem_pkg)

Status: Proposed (owner request 2026-11-25, issue 0034)

## Context

The owner wants the Mimas A7's DDR3 (MT41J128M16XX-125: 256 MiB, x16, bank
34) as a frame store for low-resolution thumbnails (issues 0035, 0036). The
brief said "no DDR3 in the baseline"; this amends it on one condition: the
baseline (capture, passthrough, console, JTAG/UART/keyboard, management)
must keep working when DDR3 does not calibrate. Clients (thumbnail writer,
network receiver, mosaic reader) are being written in parallel against the
`hdl/src/mem/mem_pkg.vhd` port contract and the `hdl/sim/mem_model.vhd`
behavioural model.

Options: Xilinx MIG 7-series (vendor IP, generated by Vivado; the PHY and
calibration are proven on this exact board by Numato's own example), or
LiteDRAM (open source, would need a Python/Migen generation step and its own
7-series PHY bring-up). Bitstreams come from Vivado by default (ADR 0001
amendment), so MIG costs nothing extra in the build.

## Decision

* **Controller: MIG 7-series v4.2**, generated in the Vivado batch build
  (`vivado/build.tcl`: `create_ip mig_7series`, `CONFIG.XML_INPUT_FILE`
  from the checked-in `vivado/ip/ddr3_mig.prj`, `generate_target`, no OOC
  checkpoint). The project file is Numato's Mimas A7 MIG configuration
  (numato/samplecode `FPGA/numatoVivadoBSP/MimasA7/1.0/mig.prj`) with the
  module renamed `ddr3_mig`, MIG 4.2 and the native (UI) port instead of
  AXI. Settings: 400 MHz memory clock (800 MT/s), 4:1 PHY (UI clock
  100 MHz, 128-bit app words = one BL8 burst), CL 6 / CWL 5, internal VREF
  0.75 V, BANK_ROW_COLUMN mapping, XADC temperature compensation.
  LiteDRAM stays the fallback if MIG ever proves impractical.
* **Clocking**: MIG system clock = the existing 200 MHz `clk_ref` (BUFG from
  the clk_sys MMCM), also its IDELAY reference ("Use System Clock"). The
  MIG XDC LOCs its PLL and MMCM to the bank-34 CMT (X1Y0); dvi2rgb keeps the
  X1Y1 MMCM (HDMI IN clock pin) and the other MMCMs (clk_sys, video, RGMII
  RX) take the remaining CMTs. This uses all 5 MMCMs of the XC7A50T and 2 of
  the 5 PLLs. The MIG clocks are auto-derived from clk_ref and join its
  asynchronous clock group.
* **Layers** (vendor-neutral except the wrapper):
  * `mem/mem_arbiter.vhd`: N client ports (`mem_req_arr_t`) -> one port,
    round robin, registered output stage, in-order read return steered by a
    tag FIFO (clk_sys).
  * `mem/mem_app_bridge.vhd`: mem port (clk_sys) -> MIG UI. Two async FIFOs
    (`common/async_fifo.vhd`, gray pointers) carry requests out and read
    data back; read credit (32) keeps the read FIFO from overflowing (MIG
    read data cannot be back-pressured). Write data is handed to the MIG
    before or with its command. Word address a -> `app_addr = a & "000"`.
  * `platform/xc7/ddr3_xc7.vhd`: MIG instance + bridge.
  * `mem/mem_selftest.vhd`: arbiter port 0, see below.
* **Failure containment**: the bridge holds `ready = '0'` until
  `init_calib_complete` (synchronised) is high, so no client request is
  ever accepted by a memory that is not there; nothing else in the design
  depends on the DDR3 clocks or reset. Clients must treat "no ready" and
  "no rvalid" as normal (thumbnail features then show colour bars / a frown).
* **Self-test** (first hardware check): once after calibration, over the top
  1 MiB (word addresses 0xFF0000..0xFFFFFF, bank 7, clear of the thumbnail
  store in bank 0): write A(a) (address mixed into all 128 bits), then
  not-A with a byte mask alternating between the two DQ byte lanes
  (exercises DM0/DM1 both ways), then read back and compare. Reports
  failing words (saturating), a 16-bit DQ fail mask (bit i of a 128-bit
  word travels on DQ i mod 16) and the first failing word address.
* **Status** goes out in the heartbeat memory block (ADR 0005 section 3b,
  datagram bytes 140..151): calibrated, self-test running/done/pass, errors,
  DQ mask, region size, first error. `dutctl listen` shows it.

## Consequences

* The Vivado build generates the MIG every time (about half a minute) and
  the openXC7 flow cannot build the design while DDR3 is in it (MIG is
  Vivado-only; the flow is paused anyway, ADR 0001).
* All MMCMs are used. A future clock needs a PLL (3 left) or sharing.
* Bank 34 is fixed at 1.5 V (DDR3); nothing else of ours is on it.
* Throughput (theoretical 1.6 GB/s, bridge one request per UI cycle at
  best) is far beyond thumbnails (~0.5 MB per 360x240 RGB565 frame).
* The mem_pkg clients keep a simple contract (valid/ready, posted writes,
  in-order reads); policy (what lives where) stays in the address map in
  `mem_pkg.vhd`.
