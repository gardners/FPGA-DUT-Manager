# 0033: EDID emulation on HDMI IN

Status: Open
Opened: 2026-11-25 (lead; design brief US-09)

HDMI IN currently releases DDC (no EDID) and asserts HPD. Real sources
(MEGA65, and later HewnWeb boards) may read EDID to choose a mode. Provide
an EDID advertising the 27 MHz modes we capture (720x480p60 and
720x576p50, DVI or HDMI as appropriate), served by dvi2rgb's DDC EEPROM
emulation (kEmulateDDC) or our own I2C slave, on the Mimas HDMI IN DDC pins
(SCL J2, SDA H2). Later (US-09): host-settable EDID and HPD control via
management.

## 2026-11-25 progress (feature/edid)

* Own vendor-neutral DDC slave `hdl/src/video/ddc_edid.vhd` instead of
  dvi2rgb's EEPROM_8b (kEmulateDDC stays false): EEPROM_8b reads its
  contents from a file path at synthesis time, which is fragile in the
  non-project Vivado flow; ours takes the EDID as a VHDL constant
  (`hdl/src/video/edid_pkg.vhd`, generated by `scripts/gen_edid.py`).
  Behaves like a read-only 24C02 at 0x50 (offset write, Sr, sequential
  read, wraps at 256; data writes ACKed and ignored; 0x30 segment pointer
  NACKed), 2-FF sync + 100 ns glitch filter, SCL input only. Runs on the
  200 MHz reference clock inside `hdmi_rx_xc7`; a write port and a read
  counter are there for US-09 (host-set EDID, heartbeat status), unused.
* EDID (256 bytes): EDID 1.3 base, DTD1 720x480p60 (preferred, 858x525,
  27.000 MHz, -H -V), DTD2 720x576p50 (864x625, 27.000 MHz, -H -V), range
  limits 50-60 Hz / 31-32 kHz / 30 MHz, name "MEGA KVM", no established or
  standard timings; CEA-861 rev 3 extension with VICs 2 (native), 3, 17, 18
  and no HDMI VSDB, so sources send DVI (no data islands, which dvi2rgb
  would mis-decode). `--preferred 576` / `--hdmi` regenerate variants.
* Pins: hdmi_rx_scl J2 (input), hdmi_rx_sda H2 (inferred open-drain
  tri-state), LVCMOS33 with weak PULLUPs; the source provides the real
  pull-ups. HPD stays asserted. DDC ports false-pathed.
* Test: `tb_ddc_edid` (I2C master model, 100 kHz sequential read of all
  256 bytes + checksums, 400 kHz random/current-address reads, wrap,
  ignored write, NACK of 0x51/0x30) compares against the generator output
  (stale package fails); `tests/scenarios/tb_ddc_edid.py` decodes the bytes
  read back (DTDs -> 720x480/858x525 and 720x576/864x625 @ 27 MHz).
* Hardware check (needs a PC on HDMI IN instead of the loopback cable):
  connect a Linux box's HDMI output to the Mimas HDMI IN, then
  `cat /sys/class/drm/card*-HDMI-A-*/edid | edid-decode` (or
  `sudo get-edid | parse-edid`; note parse-edid 3.0.2 prints DTD modelines
  without numbers, a known bug — edid-decode is the reference), and
  `xrandr` should offer only 720x480 / 720x576.
